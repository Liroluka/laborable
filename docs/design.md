# Дизайн-документ: API робочих днів і свят Іспанії

Робоча назва: **Laborable** (див. [naming.md](naming.md)). Статус: чернетка v1, 2026-11-15.
Стек: Java 17, Spring Boot 4.1, PostgreSQL 17, Flyway, Docker.

## 1. Проблема

В Іспанії свята задаються на трьох рівнях: державному, автономії та муніципалітету.
Тому відповісти на «яка дата буде через 10 робочих днів від сьогодні у Вілафранці» складно.
Це потрібне юристам і gestorías (строки подачі документів), відділам кадрів (відпустки),
інтернет-магазинам (дати доставки) та розробникам інших застосунків.

Готові API (див. [research.md](research.md)) зупиняються на рівні автономії.
Муніципальних свят у них немає, а вони якраз і ламають розрахунки строків.

## 2. Цілі та не-цілі

**Цілі v1**
- Відповідати на 4 запити: список свят, «чи робочий день», «дата через N робочих днів», «скільки робочих днів між датами».
- Знати свята трьох рівнів: державні, автономії (19 територій), муніципальні (у v1 Каталонія).
- Завантажувати дані з відкритих офіційних джерел (BOE, відкриті дані Каталонії) без ручного введення.
- Ніколи не давати «мовчки хибну» відповідь: якщо даних немає, API каже про це явно.

**Не-цілі v1**
- Юридична консультація. Це довідник, а не висновок юриста.
- Шкільні та банківські свята, години роботи магазинів.
- Муніципальні свята поза Каталонією (потрібні адаптери для бюлетенів інших автономій, див. roadmap).
- Острівні свята Канарських островів і Валь-д'Аран (див. §9).

## 3. Користувачі та сценарії

| Користувач | Сценарій |
|---|---|
| Gestoría / юрист | «Подати документ за 10 робочих днів від 2027-03-24 у Барселоні» → дата |
| HR | Скільки робочих днів у відпустці з 2027-08-02 по 2027-08-20 у Мадриді |
| Інтернет-магазин | Чи працює доставка у Вілафранці цього дня; дата доставки через 3 робочі дні |
| Розробник | Чи сьогодні свято в муніципалітеті X (для логіки свого застосунку) |

## 4. Доменні правила

### 4.1. Ієрархія свят
Свято застосовується до місця, якщо воно державне, АБО автономії місця, АБО муніципалітету місця.

| Scope | Джерело | Приклад |
|---|---|---|
| `NATIONAL` | Рядок BOE з однаковою позначкою `*` або `**` в усіх 19 стовпцях (`*` = `NATIONAL_FIXED`, `**` = `NATIONAL_SUBSTITUTABLE`) | 1 січня, 6 січня, 1 травня |
| `REGIONAL` | Решта позначених клітинок: `**` лише в частині автономій і `***` (власне свято автономії) | Jueves Santo, Sant Joan |
| `LOCAL` | Бюлетень автономії (до 2 свят на рік на муніципалітет) | Festa major |

`**` і `***` зберігаються як `REGIONAL` окремо для кожної автономії. Так обробляються заміни:
автономія може не мати Jueves Santo або мати власний Lunes de Pascua.

### 4.2. Що таке «робочий день» (v1)
Робочий день = не субота, не неділя і не свято для даного місця. Це відповідає ст. 30 Ley 39/2015 для адміністративних строків.
Інші режими (судовий із серпнем, п'ятиденний і шестиденний трудовий) винесено в профілі (roadmap).

### 4.3. Семантика операцій
- `add(date, n)`: стартова дата **не враховується**, рахуємо з наступного дня. `n < 0` іде назад. `n = 0` повертає `date`.
- `between(from, to)`: за замовчуванням `from` включно, `to` виключно (параметри `includeFrom`, `includeTo`).
- Узгодженість, яку перевіряють тести: `add(a, n) = d` ⇒ `between(a, d, includeFrom=false, includeTo=true) = n` для `n > 0`.
- Ліміти: `|days| ≤ 3660`, діапазон `between` ≤ 3660 днів (захист від зловживань).

### 4.4. Покриття даних (ключовий принцип)
Тиха помилка гірша за явну. Тому:
- Якщо для року немає офіційних даних автономії → **422** `data-not-available`, а не «свят немає».
- Якщо запит стосується муніципалітету, а місцеві свята автономії за цей рік не завантажені → `warnings: LOCAL_HOLIDAYS_NOT_LOADED`.
- Якщо регіон не вказано → застосовуються лише `NATIONAL` і є `warnings: NO_REGION`.
- Для `CN` (острови) і `CT` (Валь-д'Аран) → `SUBREGIONAL_HOLIDAYS_NOT_SUPPORTED`.

## 5. Ідентифікація місця

- Автономія: код ISO 3166-2:ES (`CT`, `MD`, `AN`, `IB`, …), 19 значень (17 автономій + `CE`, `ML`).
- Муніципалітет: **код INE (5 цифр)** є канонічним ключем. Також приймається повна назва або slug
  (`vilafranca-del-penedes`), нормалізований (регістр, діакритика, дефіси).
- Префікси не вгадуємо. `vilafranca` дає **404** з `suggestions`, а не «єдиний збіг на сьогодні»:
  інакше відповідь змінилася б після завантаження Майорки. Неоднозначна точна назва дає **409** з `candidates`.
- Якщо вказано лише муніципалітет, автономія виводиться з префікса INE (провінція → автономія, 52 рядки в міграції).
  Якщо автономія вказана і суперечить провінції → 400.

## 6. Архітектура

```
 клієнт ──HTTP──► [Spring MVC controllers] ──► [services] ──► [repositories / JdbcClient] ──► PostgreSQL
                    web/                     service/ + domain/          persistence/
 адмін  ──X-API-Key──► /admin/holidays/import ──► ImportService ──► (BOE | Каталонія) fetcher + parser
                                                      │ allow-list URL, HTTPS, ліміт розміру
```

Пакети (`app.laborable.*`):
- `domain`: чисті типи та `BusinessDayCalculator` (без Spring, тестується без БД).
- `persistence`: репозиторії на JdbcClient (читання, upsert, `ON CONFLICT`).
- `service`: `PlaceResolver`, `HolidayService`, `BusinessDayService`.
- `web`: контролери, DTO-record, `ApiExceptionHandler` (RFC 9457 problem+json).
- `imports`: `BoeAnnexParser`, `CataloniaLocalParser`, `ImportService`, `RemoteFetcher`.
- `config`: безпека, кеш, CORS, властивості.

Чому JDBC, а не JPA: модель плоска, потрібні `ON CONFLICT` і масові вставки, зв'язків «один-до-багатьох» для навантаження немає.
Менше магії, швидший старт.

## 7. Модель даних (Flyway `V1`, `V2`)

```
region(code PK, name)                         -- 19 рядків, seed
province(code PK, name, region_code FK)       -- 52 рядки, seed
municipality(ine_code PK, name, name_normalized, province_code FK)
import_run(id PK, source, year, source_ref, dry_run, status, started_at, finished_at, stats jsonb)
holiday(id PK, holiday_date, scope, kind, region_code?, municipality_ine?, name, import_run_id FK)
   CHECK: NATIONAL без регіону й муніципалітету; REGIONAL лише з регіоном; LOCAL лише з муніципалітетом
   UNIQUE (holiday_date, scope, coalesce(region_code,''), coalesce(municipality_ine,''))
coverage(year, region_code, level REGIONAL|LOCAL, status, import_run_id)  PK(year, region_code, level)
```

Індекс по `holiday_date`; вибірка за рік є діапазонним запитом. Результат кешується (Caffeine,
ключ `year|region|ine`) і скидається після кожного імпорту.

## 8. API

Спільне: `GET`, JSON, дати ISO `YYYY-MM-DD`, помилки `application/problem+json`.
`region` і `municipality` необов'язкові, див. §4.4.

| Метод | Шлях | Відповідь |
|---|---|---|
| GET | `/holidays?year=2027&region=CT&municipality=08305` | `{year, region, municipality, coverage, holidays[{date,name,scope,kind}], warnings[]}` |
| GET | `/business-days/is-working?date=2027-03-29&region=CT` | `{date, working, reason: WORKING/WEEKEND/HOLIDAY, holiday?, warnings[]}` |
| GET | `/business-days/add?date=…&days=10&region=…` | `{start, days, result, holidaysSkipped[{date,name}], warnings[]}` |
| GET | `/business-days/between?from=…&to=…&includeFrom=true&includeTo=false&region=…` | `{from, to, count, holidaysInRange[], warnings[]}` |
| POST | `/admin/holidays/import` | `{runId, source, year, dryRun, status, parsed, inserted, notes[], anomalies[]}` |
| GET | `/actuator/health`, `/v3/api-docs`, `/swagger-ui.html` | службові |

Коди помилок: 400 (невалідний ввід, діапазон), 401 (admin), 404 (місце), 409 (неоднозначний муніципалітет),
422 (немає даних за рік), 500 (без деталей усередині).

## 9. Імпорт даних (`POST /admin/holidays/import`)

Тіло: `{"source":"BOE"|"CATALONIA_LOCAL","year":2027,"boeId":"BOE-A-2026-21254","dryRun":true}`.

**BOE** (перевірено 2026-11-15 на BOE-A-2026-21254, `https://www.boe.es/diario_boe/xml.php?id=…`).
Додаток до резолюції це таблиця: рядки «число + назва», 19 стовпців автономій, у клітинках `*`/`**`/`***`.
Розбір іде за позицією стовпця, назви автономій нормалізуються, місяці є рядками-розділювачами.
Примітки під таблицею (острови Канарських, Валь-д'Аран) не імпортуються, а повертаються в `notes`.
Валідація: рік у тексті збігається із запитом, рівно 19 стовпців, у кожної автономії ≤ 14 різних дат (інакше попередження).
Збереження: у транзакції видаляємо `NATIONAL`/`REGIONAL` за рік і вставляємо нові (виправлена резолюція замінює стару), потім оновлюємо `coverage`.

**CATALONIA_LOCAL** (Socrata `analisi.transparenciacatalunya.cat/resource/b4eh-r8up.json`, 115 006 рядків, 2012–2026).
Відомі проблеми набору: старі роки містять тестове сміття (`Prueba 2`, `sal`, `abc`), загальнокаталонські дати
(`Any nou`, `La Diada`) і рядки по `pedania ≠ 000`. Правила:
1. Потрібен завантажений BOE цього року (інакше 409). Рядки з датою, що вже є святом `CT` або державним, відкидаються як дублікати.
2. Відкидаються `pedania ≠ 000`, INE не з 5 цифр, рік дати ≠ запитаний, назва без літер або з тестовим шаблоном.
3. **Юридичний інваріант** (RD 2001/1983, ст. 46): ≤ 2 місцевих свят на муніципалітет. Якщо більше, усі рядки муніципалітету йдуть в `anomalies`.
4. Зберігається `coverage(year, CT, LOCAL)`.
Для 2026: 2794 рядки, 909 муніципалітетів, усі з назвою `Festiu local`.

**Безпека імпорту:** URL будується на сервері з фіксованого allow-list (`www.boe.es`, `analisi.transparenciacatalunya.cat`),
`boeId` перевіряється регулярним виразом, редіректи вимкнені, лише HTTPS, таймаут і ліміт розміру відповіді (SSRF неможливий).
XML розбирається з вимкненими DTD і зовнішніми сутностями.
`dryRun=true` показує, що було б завантажено, і нічого не пише (окрім запису в `import_run`).

## 10. Безпека
- Публічні `GET` без автентифікації; `/admin/**` лише з `X-API-Key`. Ключ береться зі змінної `LABORABLE_ADMIN_API_KEY`,
  порівняння сталого часу, мінімум 24 символи. Якщо ключа не задано, admin вимкнено (fail-closed).
- Stateless, без cookie і CSRF. Заголовки безпеки Spring Security. CORS лише зі списку `LABORABLE_CORS_ORIGINS`.
- Усі SQL параметризовані. Помилки не розкривають шляхи, стек і SQL.
- Rate limiting у v1 у застосунку не реалізовано; обмеження на рівні реверс-проксі (Caddy/nginx). Це відомий пробіл, зафіксований у PROGRESS.
- Секрети лише у змінних середовища; в репозиторії `.env.example` без значень.

## 11. Тестування
- Unit: калькулятор (вихідні, свята, назад, перехід року, тотожність add/between), парсери (на реальній BOE-фікстурі 2027 і наборі Каталонії).
- Integration: Spring + справжній PostgreSQL (zonky embedded, без Docker): імпорт → запити → помилки → admin-авторизація.
- Ціль покриття: ~80% загалом, ≥ 90% для `domain` та `imports`. Звіт JaCoCo (`target/site/jacoco`).
- Перед релізом: незалежне ревю окремим агентом.

## 12. Розгортання
Multi-stage `Dockerfile` (Maven → JRE 17, не root). `docker-compose.yml`: `postgres:17` з healthcheck + застосунок.
Конфігурація через `.env`. Перший запуск: порожня БД (Flyway створює схему й довідники), далі імпорт через admin endpoint (`scripts/import-demo.sh`).

## 13. Етапи
1. Каркас: Spring Boot, Flyway, Docker, health. 2. Читання: `/holidays` + місце. 3. Розрахунки: три `business-days`.
4. Імпорт BOE + Каталонія + admin. 5. Загартування: ревю, rate limit, документація, реліз 0.1.0.
Перспективи й аналіз пропусків: [roadmap-analysis.md](roadmap-analysis.md).
