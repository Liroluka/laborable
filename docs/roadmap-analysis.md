# Що ще додати: аналіз

Оцінка: **Цінність** (для користувача), **Зусилля** (S ≤ 1 день, M ≤ 1 тиждень, L > тижня). Пріоритет P1 це наступні релізи.

## P1. Без цього продукт ненадійний

| Функція | Навіщо | Цінність | Зусилля |
|---|---|---|---|
| **Муніципальні свята всіх автономій** (адаптери для бюлетенів Мадрида, Андалусії, Валенсії, Балеарів…) | Зараз місцеві свята є лише в Каталонії; без них відповідь «Мадрид, Мостолес» неповна | Висока | L |
| **Довідник муніципалітетів INE** (≈ 8 100 записів, завантаження з INE) | Пошук за назвою і валідація INE-коду поза Каталонією | Висока | S |
| **Острови Канарських і Валь-д'Аран** | BOE дає це лише у примітках; потрібна таблиця `area` + відповідність муніципалітет→область | Середня | M |
| **Попередні (provisional) свята** для років без резолюції (алгоритм Великодня + фіксовані дати), статус у відповіді | Дати на 2028+ без 422, але з прапорцем «неофіційно» | Висока | M |
| **Версіонування даних і запит «станом на дату»** (`asOf`) | Юристу потрібно відтворити відповідь, яку API дав у день подачі | Висока | M |
| **Rate limiting + API-ключі для споживачів** (квоти, ключі, облік) | Захист від зловживань; основа монетизації | Висока | M |
| **Моніторинг свіжості даних** (метрики «рік X імпортовано», алерт перед 1 жовтня) | Резолюція на наступний рік виходить у жовтні; не прогавити | Середня | S |

## P2. Помітно підвищує цінність

| Функція | Навіщо | Цінність | Зусилля |
|---|---|---|---|
| **Профілі робочого тижня**: `ADMINISTRATIVE` (пн–пт), `LABOR_MON_SAT`, `JUDICIAL` (серпень inhábil, інші виключення; **перевірити з юристом**) | Різні режими дають різні дати; судові строки відрізняються | Висока | M |
| **Калькулятор строків за Ley 39/2015** (дні, місяці, роки; «з наступного дня»; перенос на наступний робочий) | Закриває основний сценарій gestoría | Висока | M |
| `GET /business-days/next` і `/previous` (найближчий робочий день) | Типова потреба інтернет-магазинів | Середня | S |
| **Puentes** (мости): `GET /bridges?year=&region=` | Популярна іспанська специфіка; корисно HR і туризму | Середня | S |
| **iCal-фід** (`/holidays.ics?region=…`) | Підписка в Google/Outlook Calendar без коду | Середня | S |
| **Пакетний запит** `POST /business-days/batch` | Інтернет-магазини рахують сотні дат за раз | Середня | S |
| **Назви кількома мовами** (es, ca, gl, eu, va, en) | Для Каталонії, Галісії, Країни Басків, міжнародних клієнтів | Середня | M |
| **Webhook / feed змін** («Мадрид змінив свято на 2027») | Системи HR не повинні пропустити виправлення | Середня | M |
| **Клієнтські SDK** (генерація з OpenAPI: Java, TS, Python) | Швидке впровадження | Середня | S |

## P3. Згодом

- Шкільні календарі (по автономіях), святкові дні закладів.
- Іспанські державні свята, що не є відпочинком (дні «inhábil» для окремих відомств, наприклад AEAT/Seguridad Social).
- Інші країни (ES → Португалія, Андорра) через ту саму модель scope.
- Адмін-інтерфейс: перегляд імпортів, ручна корекція з аудитом.
- Публічна сторінка «стан даних» з покриттям за роками й автономіями.

## Нефункціональне, чого не вистачає зараз
- **Rate limiting** і квоти (зараз лише на проксі).
- Метрики Prometheus (латентність, помилки 422, кеш-хіти) і структуровані логи.
- Бекапи PostgreSQL і політика міграцій для prod.
- Юридичний текст: умови використання, дисклеймер «не юридична консультація», політика даних (GDPR; персональних даних API не збирає, лише IP у логах).
- Ліцензії джерел: BOE і відкриті дані Generalitat; перевірити вимоги атрибуції.
- Доступність: Swagger UI публічний, потрібен контроль за тим, що не світить admin-шляхи в prod (вимкнути за потреби).

## Рекомендований порядок
1. Довідник INE → 2. Provisional-роки → 3. Профілі + калькулятор Ley 39/2015 → 4. Rate limit + ключі → 5. Інші автономії по одній (Мадрид, Валенсія, Андалусія) за обсягом користувачів.
